# 打電話給小黑｜開發任務與驗收清單

依據 2026-11-04 的產品規格 V0.3 與技術架構，版本 `3a1c4de`。以下收錄 38 項開發任務與 10 個待確認事項。各項的目前進度、測試證據與結案日期，以對應的 GitHub Issue 為準。

## ▌交付順序

第一期要讓一位 ECCAL 會員從網頁發起語音諮詢，使用本人的累計五分鐘取得顧問建議，並在通話後查看紀錄、領取成果。先用測試音色做通話驗收，聲音服務可平行評估。要對外以小黑本人的聲音提供服務，另需通過 V-02 的本人試聽與即時通話驗收。

| 工作段 | 項數 | 完成時要能驗證什麼 |
|---|---:|---|
| 第一期 M0 會員、額度與網頁通話 | 9 | 以 ECCAL 測試會員從網頁撥打一通，在後端核對用量。跨通話、搶用最後一秒、斷線與額度耗盡的測試皆通過。 |
| 第一期 M1 顧問對話與方法庫 | 5 | 用會員本人授權走完一個方法庫工具的呼叫與語音續答。人工核對追問、依據、策略與教學風格，並通過工具失敗測試。 |
| 第一期 M2 紀錄、成果與交付 | 12 | 會員可讀取自己的紀錄並領到三類成果。Email 實收、LINE 由專人監督實送、錯人拒讀、紀錄到期清除均有證據。真人交接格式可供第二期使用。 |
| 第一期整合驗收 | 3 | 在可重現的 Cloudflare 測試環境，重跑成功與異常路徑。分別登記可用語音顧問與本人音色的驗收結果。 |
| 平行項目 小黑本人聲音 | 2 | 取得本人授權與可用供應商資格。以實際通話核對音色、台灣國語、插話與延遲，由本人確認後才標示音色通過。 |
| 第二期 商業化與真人服務 | 5 | 經確認的購時、匯出、真人交接及預授權顧問個案，各自有跨系統核對結果。 |
| 第三期 一般會員自助授權 | 2 | 一般會員可就核准的資料來源自行授權，僅能分析其已授權範圍，撤銷授權後再查詢會遭拒。 |

M0、M1、M2 與 G1 是這份清單拆出的第一期工程順序。V 為平行的聲音整合。第二期各功能可按各自的前置條件安排。第三期另行開放一般會員自助授權。

## ▌怎麼用這份清單核實進度

1. 開工前先看任務的前置編號。M、G、V、B 開頭的是任務，D 開頭的是需要確認的決策或介面。可以先用模擬資料開發，涉及 ECCAL、Realtime、MCP 或交付管道的正式整合驗收須使用各自的測試服務或受控帳號。
2. 用兩位獨立的測試會員查權限。表中的秒數、商品與廣告問題都是測試資料，扣秒時間軸以 D2 簽定的規則為準。先確認身分、額度、工具授權三件事，其中任何一件失敗，都要能查明失敗在哪裡。
3. 每項通過條件均須符合。在對應 Issue 登記版本、測試環境、操作、實際結果與去識別化證據。驗收人確認通過並登記日期後，再關閉 Issue。失敗時留下預期與實際結果的差異，修正後以同一個案例重測。
4. 要交給 Codex 開發，可直接指定 Issue 及任務編號。每次交回該項的變更、測試方式與驗收證據。正式發布、真人收件與付費測試另依當次授權執行。

## ▌第一期 M0 會員、額度與網頁通話

<a name="m0-01"></a>

### M0-01　核定 ECCAL 串接契約

[#1](https://github.com/backtrue/realtime-black/issues/1)

- **前置**　D1
- **怎麼測**　在測試環境對照可用、登入失效、資格不足三種會員，讀取判定結果與可用額度。
- **何時算通過**　工程可用同一份契約驗證會員、讀取權威餘額及回寫用量。三種回應與 ECCAL 一致，欄位與錯誤條件可重現。
- **應附證據**　契約版號、測試會員對照表與去識別回應。
- **規格依據**　P3、P9、A1、A7

<a name="m0-02"></a>

### M0-02　建立 Cloudflare 測試服務與憑證邊界

[#2](https://github.com/backtrue/realtime-black/issues/2)

- **前置**　可先開始
- **怎麼測**　檢查測試版瀏覽器程式、通話設定、網路回應與紀錄，再檢視後端可用的設定。
- **何時算通過**　前端只取得該次會話必要的短效資料。永久 OpenAI 金鑰、ECCAL 服務金鑰、MCP 權杖留在後端。證據檔不含密鑰。
- **應附證據**　測試環境版本、去識別的請求紀錄與程式檢查結果。
- **規格依據**　R、A1、A2、A3

<a name="m0-03"></a>

### M0-03　限合格會員領取通話憑證

[#3](https://github.com/backtrue/realtime-black/issues/3)

- **前置**　M0-01、M0-02
- **怎麼測**　用有效且有額度、未登入、失效、無資格、餘額零五種身分直接呼叫發憑證端點。另竄改會員編號。
- **何時算通過**　只有有資格且有額度者能為自己建立通話。其餘均無可用憑證。改會員編號不能冒用別人的資格，過期憑證無法新建通話。
- **應附證據**　各案例的後端結果與會話建立紀錄。
- **規格依據**　P3、P8、A2、A3

<a name="m0-04"></a>

### M0-04　完成一鍵撥打、插話與掛斷

[#4](https://github.com/backtrue/realtime-black/issues/4)

- **前置**　M0-03
- **怎麼測**　在實際瀏覽器授權麥克風，從網頁撥打、發問、在回答途中插話、接續追問並掛斷。另測拒絕麥克風。
- **何時算通過**　會員在開始前看見「AI 小黑」，可聽見答覆，插話後舊回覆停止且下一題接得上。掛斷後音訊停止，拒絕授權時畫面正確反映未接通。
- **應附證據**　測試瀏覽器與版本、去識別事件線與人工聽測紀錄。
- **規格依據**　P1、P8、A1、A2、A7

<a name="m0-05"></a>

### M0-05　計算每位會員跨通話的 300 秒

[#5](https://github.com/backtrue/realtime-black/issues/5)

- **前置**　D2、M0-03
- **怎麼測**　以核定計時規則，使同一會員兩通各產生 120、180 個應扣秒。兩通之間重新登入並重新整理頁面，再查另一會員。
- **何時算通過**　該會員餘額依序為 300、180、0 秒。重登或換裝置不會重新取得 300 秒，另一會員餘額維持原值。每筆扣秒能對回個別通話。
- **應附證據**　時間軸、兩筆用量及 ECCAL 前後餘額。
- **規格依據**　P3、P8、A1、A4

<a name="m0-06"></a>

### M0-06　避免多分頁與多裝置重複用額

[#6](https://github.com/backtrue/realtime-black/issues/6)

- **前置**　M0-05
- **怎麼測**　同一會員只剩 1 個可用秒，在兩個分頁及兩台裝置同時按撥打。重送開始與結束請求。
- **何時算通過**　兩個會話合計可消耗的額度最多 1 秒。重放相同請求不會重發試用或重扣。服務端與 ECCAL 帳目一致。
- **應附證據**　並行請求時間、兩個回應、用量與最終餘額。
- **規格依據**　P3、P8、A2、A4

<a name="m0-07"></a>

### M0-07　用盡額度後由後端停止通話

[#7](https://github.com/backtrue/realtime-black/issues/7)

- **前置**　M0-04、M0-05
- **怎麼測**　把測試會員剩餘秒數調低，停用前端倒數，持續講話至額度用完。用原連線送新問題，再另外要求新憑證。
- **何時算通過**　後端可終止既有會話或阻止後續計費使用，原連線不能繼續付費互動，也領不到新憑證。以後端與提供者事件核對截止點。
- **應附證據**　後端終止或拒絕事件、提供者會話紀錄及餘額。
- **規格依據**　P3、P8、A2、A7

<a name="m0-08"></a>

### M0-08　處理斷線、等待工具及重複結算

[#8](https://github.com/backtrue/realtime-black/issues/8)

- **前置**　D2、M0-04、M0-05
- **怎麼測**　依核定時間軸模擬工具等待、斷網、關分頁、重連與重複送達結束事件，逐案對帳。
- **何時算通過**　各案例扣秒符合 D2。同一段使用只結算一次，舊會話未占用多餘額度，下一次通話從正確餘額開始。
- **應附證據**　事件重放紀錄、預期與實扣秒數對照。
- **規格依據**　P3、P8、A4、A7

<a name="m0-09"></a>

### M0-09　處理通話未接通與憑證失效

[#9](https://github.com/backtrue/realtime-black/issues/9)

- **前置**　D2、M0-03、M0-04
- **怎麼測**　讓短效憑證過期才連線，另測 Realtime 拒絕建立會話及網路在接通前中斷，再重開網頁查可用額度。
- **何時算通過**　畫面與服務端同時反映未接通。未使用的占用額度可以釋放，依 D2 核定的事件結算。重新登入不能製造額外秒數。
- **應附證據**　憑證拒絕回應、會話狀態、前後餘額。
- **規格依據**　P3、P8、A2、A7
